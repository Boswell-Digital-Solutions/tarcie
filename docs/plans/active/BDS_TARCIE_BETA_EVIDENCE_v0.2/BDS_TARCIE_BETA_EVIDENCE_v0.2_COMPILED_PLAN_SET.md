# BDS-TARCIE-BETA-EVIDENCE-v0.2 - Compiled Plan Set

This compiled entry binds the canonical component files in this folder. The
component files control where a summary conflicts with detailed language.

## Decision

Propose Tarcie as a guided human beta-testing companion that loads a bounded
assignment package, presents product sections at Start Session, preserves fast
capture during the run, and displays a writable PDF closeout at End & Review.
Finalize creates a structured, hash-bound local candidate evidence package.

Tarcie and Author_Forge must be installable and operational on Windows, macOS,
and Linux. Installed workflow proof, not artifact generation, is the support
gate. Windows-only Scrivener qualification remains a narrower integration claim.

## Architecture

- Forge_Command: assignment/package/lifecycle/receipt authority.
- Tarcie: human guidance, local capture, section coverage, report workspace.
- DataForge Local: accepted fact/artifact storage without semantic authority.
- Forge:SMITH: policy and review gates.
- Human tester: capture, correction, redaction, report, final approval.
- Charlie Boswell: work-package and release authorization.

## Core flow

`LOAD -> READY -> START -> ACTIVE <-> PAUSED -> END & REVIEW -> FINALIZE`

Delivery and acceptance are separate transactions. No GitHub issue or code
mutation is automatic.

## Gates

1. Current-source lock.
2. Strict schemas, canonicalization, fixtures, threat model, and PDF field map.
3. Non-executable session loader and Session Hub.
4. Crash-safe session lifecycle and coverage.
5. Explicit capture and reviewed artifacts.
6. Writable PDF and structured round-trip.
7. Localhost receiver and hash-bound receipts.
8. Installed qualification on Windows, macOS, and Linux.
9. Limited human beta and Board Review 2.
